# 从零开始学机器学习 #02：梯度下降——所有模型"学"的那只手

想象你被蒙上眼睛，扔在一座山的半山腰。任务是走到谷底，但你什么都看不见。

你会怎么办？

大概率你会用脚试探四周，感觉哪个方向最陡，就朝那个方向迈一步。到了新位置，再试探，再迈一步。只要每一步都朝着"脚下最陡的下坡方向"走，早晚能摸到谷底。

这个笨拙又可靠的办法，就是**梯度下降**。今天几乎所有机器学习模型——从线性回归到千亿参数的大模型——"学习"时靠的都是它。

![梯度下降像蒙眼下山每步走最陡方向](downhill.png)

上一篇我们说到，机器学习的"学习"就是在损失这个碗里找最低点。但也留了个尾巴：参数一多，把碗里每个点都摸一遍（暴力搜索）就彻底算不过来了。梯度下降就是那个不用摸遍全场、站在一点就知道往哪走的聪明办法。

## 上一篇的遗留问题：为什么不能一个个试

先说清楚梯度下降到底解决了什么，不然你不会体会到它的妙。

上一篇的暴力搜索，思路是把参数的每个可能取值都试一遍，挑损失最低的。两个参数、每个试 100 个值，要算一万次。这还能忍。

可参数一多就完了。假设有 10 个参数，每个试 100 个值，就是 100 的 10 次方——一个 20 位数。就算每秒算十亿次，也要跑上百万年。

真实模型的参数远不止 10 个。梯度下降不去试所有组合，它只做一件事：站在当前这个点，算出"往哪个方向走，损失会下降最快"，然后朝那个方向挪一小步。

说白了就是：暴力搜索是把地图上每个格子都走一遍，梯度下降是每次只看脚下、朝下坡方向走。后者快得不是一点半点。

## 梯度：告诉你哪个方向下降最快

蒙眼下山时，你靠脚感判断哪个方向最陡。机器靠什么？靠**梯度**。

梯度是个数学工具，它能告诉你：在当前这个参数位置上，损失朝哪个方向增加得最快。那朝相反方向走，损失就下降得最快。这就是"梯度下降"名字的由来——沿着梯度的反方向下降。

好在梯度不用猜，有公式直接算。对我们上一篇那个 `y = wx + b` 的模型，损失对参数 `w` 的梯度长这样：

```python
def gradient(w, b, X, y):
    """损失对 w、b 的偏导数——指向损失上升最快的方向"""
    err = (w * X + b) - y
    dw = 2.0 * np.mean(err * X)   # 损失对 w 的梯度
    db = 2.0 * np.mean(err)       # 损失对 b 的梯度
    return dw, db
```

不用纠结公式怎么推的。你只要知道：给定当前的 `w`、`b`，这几行代码能算出"往哪个方向调，损失涨得最快"。取个负号朝反方向走，就是下坡。

有了方向，剩下的就是不停地迈步：

```python
def fit(X, y, lr=0.05, n_iters=1000):
    w, b = 0.0, 0.0
    for _ in range(n_iters):
        dw, db = gradient(w, b, X, y)
        w -= lr * dw    # 朝下坡方向挪一步
        b -= lr * db
    return w, b
```

整个梯度下降就这么点东西：算梯度、往反方向挪一步、重复。就这几行，是几乎所有模型训练的核心。

那它比暴力搜索快多少？我把两种办法在同一份数据上跑了一遍，对比它们要算多少次才能找到答案：

![梯度下降与暴力搜索的代价对比](gd_vs_grid.png)

暴力搜索光两个参数就要算几千次，梯度下降几十步就到位了。参数越多，这个差距越夸张——这就是为什么全世界的模型都用梯度下降，没人真的去暴力搜。

## 学习率：一步迈多大，是门大学问

有了方向，还有个关键问题没解决：每一步迈多大？

这个"步子大小"，就是**学习率**。代码里那个 `lr`。它是梯度下降最重要、也最容易翻车的一个设置。

步子太小，你磨磨蹭蹭往下挪，走到谷底要花很久。步子太大，你可能一步直接跨过谷底，落到对面的山坡上，甚至越走越高——彻底跑飞。

光说没感觉，看真实数据。我用三个不同的学习率跑同一个问题，把损失随迭代次数的变化画出来：

![学习率太小太大与合适的收敛对比](lr_comparison.png)

看这张图（纵轴是对数刻度）。学习率 0.1（橙线）收敛得又快又稳，几步就贴到底了。0.01（蓝线）太小，慢吞吞地降，磨蹭。而 0.9（绿线）——注意它是往上冲的——步子太大，每一步都跨过谷底还越跨越远，损失不降反升，直接发散。

这就是初学者训练模型时踩的第一个坑：损失突然变成一个巨大的数，甚至变成 `NaN`。八成不是代码写错了，是学习率设太大了。**这不是 bug，是梯度下降的固有脾气。**

调学习率没有万能公式，更多是经验：先从 0.01 或 0.1 试，看损失曲线。降得太慢就调大点，开始震荡或发散就调小点。这个"看着损失曲线调步子"的手感，是每个做机器学习的人都要练的基本功。

## 看着它一步步走到谷底

最后，我们把整个过程可视化，让你亲眼看到参数是怎么"走"的。

这里要澄清一个很多人搞混的点：**梯度下降移动的是参数，不是损失函数。** 损失函数是那片固定不动的地形——山长什么样，一开始就定死了。参数才是那个在地形上滚动、寻找谷底的小球。

![损失是不动的地形参数是滚动的小球](terrain_ball.png)

地形（损失函数）从头到尾没变过，变的是小球（参数）的位置。训练，就是让这个小球从随便扔的起点，一步步滚到地形的最低处。

把两个参数 `w`、`b` 的移动轨迹画在损失的等高线上，看得更清楚：

![梯度下降参数一步步走向谷底](gd_trajectory.png)

黑方块是随便选的起点，红星是谷底。中间那条红线，就是参数一步步挪动的轨迹。注意开头几步跨得大——因为山坡陡、梯度大；越接近谷底步子越小——因为地势平、梯度小。它自己会"减速",稳稳停在最低点。

这条轨迹就是"学习"发生的全过程。你现在不只知道机器在找损失最低点，还知道了它是怎么找的：算梯度定方向，用学习率定步长，一步步滑下去。

下一篇会聊一个反直觉的麻烦：当模型把损失降得太低、把训练数据学得太"完美"时，反而会出大问题。这个坑叫过拟合，是每个机器学习模型都要提防的头号敌人。

蒙眼下山的比喻记住了吗？下次你训练模型看到损失曲线，脑子里就该浮现那个画面：一个小球，正沿着地形往谷底滚。
